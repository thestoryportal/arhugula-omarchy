freezes the exact candidate revision and evidence. The reviewer independently

## Continuous work and concurrency

**NEVER IDLE WORKFLOW:** coders select and immediately begin eligible released LIT
work without routine Buford assignments; reviewers pull ready
independent candidates and act on reserved review requests. Authors act immediately on delivered
findings; senders trigger the reserved recipient and verify uptake, including after
the recipient's previous turn ended. "I posted the comment" is not a reason to
leave pending pair work idle. After source/writer release, continue with another eligible
slice; hand off only at actual context/ownership boundaries. Keep useful authorized LIT work moving without routine
human confirmation. A claim or plan is a starting point: implement and check the
work, freeze the candidate, then send it directly to the reserved independent reviewer. Do not
stop at "I'll start next unless you redirect" or create a new HIL gate for released
work. Buford nudges idle lanes using current LIT and native state; it does not
clear active writers or relay routine review exchanges. Standing authorization
uses normal approval mechanisms; an actual denial or later hold remains binding.
The existing authors and reviewer pool may progress concurrently in isolated
worktrees with actual ownership and review capacity. Potential file overlap is not a reason to
serialize ready work; evaluate and reconcile real crossover at Git gates while
preserving review/CI on the resulting revision. Real uncontrolled shared effects
and an occupied Runtime window remain concrete constraints.

A dependency holds the transition that needs its output. Current LIT may explicitly
authorize isolated inactive implementation before an upstream binding is available,
while retaining the actual prerequisite for candidate freeze, integration or activation.
The accepted release campaign explicitly permits independent A5/A4 preparation
and moves assurance-only installed gates to shared final qualification after a

Record the authorized slice and the exact retained gate in the existing ticket;
