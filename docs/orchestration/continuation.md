# Bounded continuation v1

Read-only inspection: `python3 -m ops.orchestration.runner plan`.
Live use requires an isolated branch, clean linked worktrees, and an explicitly
trusted local worker/verification configuration. No shell commands are taken
from tickets or generated by the routing layer.

```json
{
  "goal": "Complete repository-only fixtures",
  "worker_argv": ["/absolute/path/to/approved-worker"],
  "verify_argv": ["python3", "-m", "unittest", "discover", "-s", "tests", "-v"]
}
```

```sh
python3 -m ops.orchestration.runner run --config /absolute/approved-config.json --tickets 2 --seconds 1800
```

Worker input is JSON on stdin: active ticket, parent epic, branch, worktree,
model, effort, role, goal, prior completed work/evidence/risks, epic and ticket
bodies, and supervisor instructions. Output is one JSON receipt:

```json
{"files":["tests/new_fixture.json"],"summary":"Added the requested fixture; no new decisions","risks":[],"stop_reason":null}
```

The worker implements only the selected unit. It cannot authorize work. It
must report privilege, destructive actions, human decisions, external access,
or context exhaustion as stop_reason and leave the unit open. Follow-up work
is filed through LIT while context is available. This bootstrap does not
execute ticket prose or install persistent services. The worker is trusted
code; a JSON receipt and advisory Git checks are not a sandbox for malicious
executables. Use Codex's workspace-write sandbox for model workers.

The supervisor holds an exclusive flock in the Git common directory across
all linked worktrees, through the child process lifetime. There is no TTL
takeover that could double-assign a slow worker. It reads unfiltered `lit next`,
descends containers by rank, checks ancestor dependencies from `lit export`,
routes safety/model metadata, inspects all Git worktrees, and uses `lit start`
without takeover. It then reads the epic/ticket and rechecks Git before work.

It verifies with the trusted argv, at most twice, records evidence and the
worker's decision summary in LIT, stages only literal receipt paths, commits,
checks cleanliness, closes via `lit done`, writes the durable handoff, and
reads `lit next` again. It stops at the configured ticket/time boundary.
Time is checked between units; each command and worker also has a timeout.
This is a bounded workload, not a hard wall-clock deadline for the whole run.
No push or merge is automatic. Publish separately after branch ownership and
clean-tree verification.

HIL, needs-design, privilege, destruction, external credential/network labels,
missing autonomy metadata, ambiguous routing, claim/lease conflict, foreign
changes, changed HEAD, deletion, symlink changes, two failed verifications,
failed commands, worker crash/timeout, empty queue and container reconciliation
all stop continuation. Exhausted containers are not silently closed: their
circle-back evidence must be reconciled first. Failure leaves the ticket open
or in_progress, never falsely done. Two verification attempts do not authorize
blind repair. Existing foreign changes are never staged or reset.

Recovery state is `<git-common-dir>/orchestration/handoff.json`, private and
atomically replaced. An `interrupted` record is written before claiming and
again after committing but before close. A crash requires comparing that
record, Git history and LIT before resolving the stop. Do not rerun committed
work blindly. An OS crash releases flock; it does not transfer a LIT claim.
Keep the previous handoff when starting a fresh session. A new process must
revalidate all authority and model metadata before consuming queued context.
The runner loads prior completed work, evidence and risks and passes them to
the next worker; branch/worktree mismatch refuses resume. The goal comes from
the explicit run configuration. `lit next` exit 1 with the exact LIT 0.14
"no ready work" diagnostic is normal exhaustion, not a command failure.

Known LIT 0.14.0 behavior: `lit next` may return a container, and `--type task`
may surface a leaf despite an ancestor prerequisite. The adapter descends
unfiltered selection and checks ancestors. Export v2 stores a `blocks` row
with blocked issue as src_id and prerequisite as dst_id, verified against
this repository's `lit show` output. Tests pin this boundary.

Foreign writers that ignore the common lease are detected by dirty-tree and
HEAD checks, but Git provides no universal session registry. Do not run other
editors/agents on the same ticket or files. A timeout kills the owned process
group before releasing the lease. Detached tmux launch plans are for managed
interactive use; they cannot be fed to this synchronous supervisor, because
they return before the editing process finishes.

Disable by not invoking `run`. No live Omarchy, service, audio, host, package
or network configuration changes are required.

Integration validation: `python3 -m unittest discover -s tests -v` includes
real LIT stores in temporary repositories (no remote, hooks disabled), linked
worktrees, subprocess workers, commits and closes, then a fresh supervisor
process consuming the durable handoff. An offline worker records routed
model/effort and prior evidence. This proves transport/continuation mechanics;
it does not claim a paid model-provider session was launched or evaluated.
Codex launch argv is separately tested against the installed CLI contract.
